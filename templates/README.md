# 模板使用说明

状态：草稿，待审阅。所有模板由本仓库依据已确定需求独立编写；概念参考和适配差异见 [来源记录](../SOURCES.md)。状态、交接、证据及知识同步遵循 [workflow.md](../workflow.md)。

| 模板 | 业务项目建议文件 | 使用时机 |
| --- | --- | --- |
| [PRD](prd.md) | 功能目录内 prd.md | 需求澄清 |
| [技术方案](technical-design.md) | technical-design.md | 技术设计，独立引用 PRD |
| [任务单](task.md) | tasks/T-001.md，每任务一份 | 拆分与开发实施共用 |
| [测试文档](test.md) | test.md | 计划先写，实际结果执行后写 |
| [产品验收](acceptance.md) | acceptance.md | 对照预先确定的 AC |
| [收尾](closeout.md) | closeout.md | 交付整理及知识同步 |
| [长期模块文档](module.md) | 已有模块文档；无入口时可用 docs/modules/模块名.md | 持续维护，不按任务重建 |
| [会话交接](handoff.md) | 按项目约定的临时或任务位置 | 换会话／执行者且确有交接需要时 |

完整功能默认使用前六类产物；小型修改可以按流程合并成一份文件，保留分开的需求与方案段落和必要验证、验收、知识同步信息。任务索引如有，仅放标题和链接，不复制状态。

`{{说明}}` 是待填写占位符，不是有效内容。复制后替换为具体值或明确的“不适用＋理由”。必需未知信息写“待确认＋影响＋下一步”，不可留空或伪造。表格示例 R-001／AC-001／T-001／TC-001 只是首行结构，按需扩展；普通表格链接应在实际项目填为有效 Markdown 链接，原始模板故意不指向不存在的业务文件。

标为“按需”的章节只保留相关项，其余删除；核心段落不可因合并省略。相同执行批次共用版本环境字段，若部分用例条件不同须新增批次。模板中的状态词选项是说明，不是执行结果；默认状态保持草稿／待确认／未运行。

产物放进业务项目后，模板顶部的流程与来源关系以本说明为准；业务项目自行保存本仓库版本入口，避免复制一份持续漂移的流程规则。
